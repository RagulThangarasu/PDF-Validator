Link check & Guide A ⇄ B

Paste the guide URLs, one per line. Each guide is crawled through its own left navigation, and every link in a topic's body is captured - its text and its address. The link's own page is never opened or crawled: the address is only asked what it answers. There is no prod PDF and no comparison. A link fails when its address carries a DITA GUID (in the address or in the label), when it redirects onto a GUID address, or when it does not answer (HTTP 4xx / 5xx, no response, a dead #anchor). Each topic is reported with its own GUID, read from the page.

The guides on the AEM author server need an AEM login: AEM answers a request without a session with its own sign-in page, so without it every topic would come back as “AEM Sign In”. Leave the two fields empty to use the login saved on the Runs page.

Validating one guide tree against another (A ⇄ B)? List the publications under the “AEM Sites folder — A” and “AEM Sites folder — B” boxes below - once both are listed, a Validate A ⇄ B button appears for the products both trees share. It crawls every topic of each product's left navigation on both sides (not just the one page you may have pasted above) and compares every rendering: text, tables, images, layout measures, and a side-by-side screenshot of each difference - a combined PDF/CSV report is built when it finishes.
